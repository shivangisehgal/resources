## Topic 15 — Scalability & High Availability Concepts

Covers: vertical vs horizontal scalability, elasticity, high availability (passive vs active), scale up/down vs out/in, and how ASG and ELB deliver these on EC2.

**Q1.** A single-node relational database is CPU-bound. The team moves it from a t2.micro to a t2.large. What kind of scaling is this?

- A. Horizontal scaling (scale out)
- B. Vertical scaling (scale up)
- C. High availability
- D. Elasticity

**Answer: B.** Vertical scalability means increasing the size of the instance (t2.micro to t2.large). It's very common for non-distributed systems such as databases.

*Why not the others:* A — that adds instances. C — HA means running in at least 2 AZs. D — the slide equates elasticity with horizontal scaling.

**Q2.** What is the main limitation of vertical scaling, per the slides?

- A. It requires a load balancer
- B. There's usually a hardware limit to how much you can vertically scale
- C. It only works for web apps
- D. It requires multiple AZs

**Answer: B.** There's usually a limit (hardware limit). The range on EC2 runs from t2.nano (0.5 GB RAM, 1 vCPU) to u-12tb1.metal (12.3 TB RAM, 448 vCPUs).

*Why not the others:* A — an LB is for horizontal scaling. C — vertical scaling suits databases. D — that's HA.

**Q3.** Which AWS services are given as examples that scale vertically? (Choose TWO.)

- A. Amazon RDS
- B. Amazon ElastiCache
- C. Route 53
- D. IAM
- E. CloudFront

**Answer: A and B.** The slide names RDS and ElastiCache as services that can scale vertically.

*Why not the others:* C, D and E — not instance-sized services; vertical scaling doesn't apply.

**Q4.** A stateless web app's traffic grows 10x during a sale. The team adds more EC2 instances behind a load balancer. What is this called?

- A. Scale up
- B. Scale out (horizontal scaling / elasticity)
- C. Passive high availability
- D. Vertical scaling

**Answer: B.** Horizontal scaling increases the number of instances (scale out/in). It implies distributed systems and is common for modern web apps.

*Why not the others:* A and D — increase instance size. C — passive HA is a standby (e.g., RDS Multi-AZ), not more serving capacity.

**Q5.** What's the stated goal of high availability?

- A. To handle greater loads
- B. To survive a data center (AZ) loss
- C. To reduce cost
- D. To lower latency for global users

**Answer: B.** HA means running in at least 2 data centers (AZs) so you survive the loss of one.

*Why not the others:* A — that's scalability; related but different. C — HA usually costs more. D — a proximity concern.

**Q6.** RDS Multi-AZ keeps a standby that doesn't serve traffic until failover. Which kind of HA is this?

- A. Active HA
- B. Passive HA
- C. Horizontal scaling
- D. Vertical scaling

**Answer: B.** The slide uses RDS Multi-AZ as the example of passive HA; horizontal scaling across AZs is active HA.

*Why not the others:* A — active HA means all nodes serve traffic. C and D — scaling, not HA mode.

**Q7.** Which combination gives an EC2 web app both horizontal scaling and high availability?

- A. One large instance in one AZ
- B. An Auto Scaling Group and a Load Balancer, both multi-AZ
- C. A cluster placement group
- D. Vertical scaling plus an Elastic IP

**Answer: B.** Horizontal scaling uses ASG + Load Balancer; HA means running them multi-AZ.

*Why not the others:* A — a single point of failure. C — single AZ. D — still one instance.

**Q8.** Which term pair is correct?

- A. Vertical = scale out/in; horizontal = scale up/down
- B. Vertical = scale up/down; horizontal = scale out/in
- C. Both = scale out
- D. HA = scale up

**Answer: B.** Vertical: increase instance size (scale up/down). Horizontal: increase number of instances (scale out/in).

*Why not the others:* A — reversed. C and D — mix concepts.

**Q9.** Which statement about scalability and high availability is correct?

- A. They're identical
- B. They're linked but different; HA usually goes hand in hand with horizontal scaling
- C. HA requires vertical scaling
- D. Scalability requires multiple Regions

**Answer: B.** The slide says scalability is linked to, but different from, HA, and HA usually goes hand in hand with horizontal scaling.

*Why not the others:* A — different goals (load vs failure survival). C — vertical scaling doesn't add AZs. D — neither requires multiple Regions.

**Q10.** Why is horizontal scaling described as easy in AWS?

- A. Because of cloud offerings such as Amazon EC2 that let you add instances quickly
- B. Because databases don't need it
- C. Because instances never fail
- D. Because it needs no load balancer

**Answer: A.** The slide credits cloud offerings like EC2.

*Why not the others:* B, C and D — unrelated or false.

## Topic 17 — Application Load Balancer (ALB)

Covers: Layer 7 features, HTTP/2 and WebSocket, redirects, routing rules (path, hostname, query string, headers), containers and ECS dynamic ports, target group types, health checks per target group, client IP headers.

**Q1.** A site must route example.com/users to one service and example.com/posts to another, behind one load balancer. Which LB and feature?

- A. NLB with TCP rules
- B. ALB with path-based routing to different target groups
- C. CLB with two listeners
- D. GWLB

**Answer: B.** ALB routing tables send requests to target groups based on the URL path.

*Why not the others:* A — Layer 4 doesn't see URL paths. C — CLB can't route by path; you'd need multiple CLBs. D — for virtual appliances.

**Q2.** A SaaS serves one.example.com and other.example.com from different backend fleets behind one LB. Which ALB feature?

- A. Host-based routing (hostname in URL)
- B. Path-based routing
- C. Sticky sessions
- D. Cross-zone load balancing

**Answer: A.** ALB can route based on hostname.

*Why not the others:* B — same host, different path. C — pins users to instances. D — distributes evenly across AZs.

**Q3.** Mobile users (?Platform=Mobile) must go to EC2-based target group 1, and desktop users (?Platform=Desktop) to an on-premises server via private IP. What makes this possible?

- A. ALB query-string routing, with target group 2 of type IP address (private IP)
- B. NLB with UDP
- C. Route 53 geolocation
- D. CLB with TCP

**Answer: A.** ALB routes on query strings/headers, and IP-address target groups can point at on-premises servers using private IPs.

*Why not the others:* B — can't inspect query strings. C — routes by user location, not URL parameters. D — no query-string routing.

**Q4.** Which are valid ALB target group types? (Choose TWO.)

- A. Lambda functions (the HTTP request is translated into a JSON event)
- B. IP addresses — must be private IPs
- C. Public IP addresses on the internet
- D. S3 buckets
- E. Another ALB

*Why not the others:* C — IPs must be private. D — not a target type. E — an NLB can target an ALB, not the other way around.

**Q5.** At what level are ALB health checks configured?

- A. The load balancer level only
- B. The target group level
- C. The listener level
- D. The AZ level

**Answer: B.** Health checks are at the target group level, so each application can have its own check.

*Why not the others:* A, C and D — not where ALB health checks live.

**Q6.** A web server behind an ALB logs only private IPs as the client address. How does the app get the real client IP?

*Why not the others:* A — ALBs don't take EIPs, and it wouldn't help anyway. C — an unnecessary architecture change. D — the header exists.

**Q7.** Which headers does an ALB add for the original request details? (Choose TWO.)

*Why not the others:* C, D and E — not on the slide.

## Topic 18 — Network Load Balancer & Gateway Load Balancer

Covers: NLB Layer 4 performance, static IP per AZ and Elastic IPs, NLB target groups (EC2, private IP, ALB) and health check protocols; GWLB for third-party appliances, Layer 3, transparent gateway, GENEVE on 6081, GWLB targets.

**Q1.** A trading platform needs millions of requests per second with ultra-low latency over TCP. Which load balancer?

- A. ALB
- B. NLB
- C. CLB
- D. GWLB

**Answer: B.** NLB (Layer 4) forwards TCP & UDP, handles millions of requests per second with ultra-low latency — for extreme performance.

*Why not the others:* A — Layer 7, higher overhead. C — old generation. D — for appliances.

**Q2.** A bank's partners can only whitelist fixed IP addresses for your API. The API must be load balanced. What's the best option?

- A. ALB (fixed hostname only)
- B. NLB, which has one static IP per AZ and supports assigning Elastic IPs
- C. CLB with an EIP
- D. Route 53 simple routing to instance IPs

**Answer: B.** NLB's static IP per AZ and Elastic IP support are explicitly helpful for whitelisting specific IPs.

*Why not the others:* A — ALB IPs can change; it exposes a hostname. C — CLB has a fixed hostname, no EIPs. D — no load balancing or health-aware failover.

**Q3.** A team needs fixed IPs for whitelisting AND path-based HTTP routing. Which architecture fits?

- A. NLB in front of an ALB (ALB as an NLB target group)
- B. ALB with Elastic IPs
- C. CLB with SNI
- D. GWLB in front of an ALB

**Answer: A.** NLB target groups can be EC2 instances, private IPs, or an Application Load Balancer, so the NLB provides static IPs and the ALB does L7 routing.

*Why not the others:* B — ALB doesn't support EIPs. C — CLB doesn't support SNI or path routing. D — GWLB targets are appliances (EC2/IPs), not ALBs.

**Q4.** Which are valid NLB target group types? (Choose TWO.)

- A. EC2 instances
- B. Application Load Balancer
- C. Lambda functions
- D. Public internet IPs
- E. S3 buckets

**Answer: A and B.** NLB targets: EC2 instances, IP addresses (must be private), and an ALB.

*Why not the others:* C — Lambda is an ALB target. D — IPs must be private. E — not a target type.

**Q5.** Which protocols can NLB health checks use?

- A. TCP only
- B. TCP, HTTP and HTTPS
- C. UDP only
- D. ICMP

**Answer: B.** NLB health checks support TCP, HTTP and HTTPS. The NLB diagram shows an HTTP check on one target group and a TCP check on another.

*Why not the others:* A — incomplete. C and D — not listed.

**Q6.** A company must inspect all inbound VPC traffic with a fleet of third-party firewall/IDS appliances, scaling them and keeping a single entry/exit point. Which service?

- A. Gateway Load Balancer
- B. NLB

**Answer: A.** GWLB deploys, scales and manages fleets of third-party network virtual appliances (firewalls, IDS/IPS, deep packet inspection, payload manipulation).

*Why not the others:* B and C — balance application traffic; they aren't transparent gateways. D — old generation.

**Q7.** Which TWO functions does GWLB combine? (Choose TWO.)

- A. Transparent network gateway — a single entry/exit for all traffic
- B. Load balancer — distributes traffic to your virtual appliances

**Q8.** An exam question mentions "GENEVE protocol on port 6081". Which service is it describing?

- A. NLB
- B. GWLB
- C. ALB
- D. Route 53

**Answer: B.** GWLB uses the GENEVE protocol on port 6081.

*Why not the others:* A, C and D — don't use GENEVE.

**Q9.** At which OSI layer does GWLB operate?

**Answer: C.** GWLB operates on IP packets at Layer 3.

## Topic 19 — Sticky Sessions & Cross-Zone Load Balancing

Covers: which LBs support stickiness, cookie expiration, imbalance risk, cookie types and names (custom, AWSALBAPP, AWSALB, AWSELB, reserved names), cross-zone traffic math, and per-LB defaults and charges.

| LB | Cross-zone default | Inter-AZ data charge if enabled |
| --- | --- | --- |
| ALB | Enabled (can disable at target group level) | No |
| NLB & GWLB | Disabled | Yes ($) |
| CLB | Disabled | No |

**Q1.** Users of a legacy web app lose their shopping carts when their next request hits a different instance. Without rewriting the app, what LB feature helps?

- A. Sticky sessions (session affinity)
- B. Cross-zone load balancing
- C. Connection draining
- D. SNI

**Answer: A.** Stickiness sends the same client to the same instance, so the user doesn't lose session data.

*Why not the others:* B — spreads load evenly, the opposite effect. C — for deregistration. D — for certificates.

**Q2.** Which load balancers support sticky sessions, per the slides? (Choose TWO.)

- A. Application Load Balancer
- B. Network Load Balancer
- C. Gateway Load Balancer
- D. Route 53
- E. CloudFront only

**Answer: A and B.** Stickiness works for CLB, ALB and NLB.

*Why not the others:* C — not listed. D and E — not load balancers in this sense.

**Q3.** After enabling stickiness, the ops team notices some instances are overloaded while others sit idle. Why?

- A. A bug in ALB
- B. Enabling stickiness may bring imbalance to the load across backend instances
- C. Cross-zone was disabled
- D. The cookie expired too fast

**Answer: B.** That is a stated downside of stickiness.

*Why not the others:* A — expected behavior. C — cross-zone isn't the root cause here. D — short expiry would reduce stickiness and so reduce imbalance.

**Q4.** For which load balancers can you control the stickiness cookie's expiration date?

- A. CLB and ALB
- B. NLB only
- C. GWLB
- D. None

**Answer: A.** For both CLB & ALB the cookie has an expiration date you control.

*Why not the others:* B, C and D — contradict the slide.

**Q5.** A developer wants the app itself to generate a stickiness cookie containing custom attributes. Which cookie type, and what naming rule applies?

- A. Duration-based cookie named AWSALB
- B. Application-based custom cookie generated by the target; name set per target group; must NOT use AWSALB, AWSALBAPP or AWSALBTG

- D. Any name, including AWSALB

**Answer: B.** Custom cookies are generated by the target, can include any custom attributes, and are named individually per target group; those three names are reserved for ELB.

*Why not the others:* A — that's generated by the LB. C — AWSELB is the CLB duration cookie. D — reserved names are forbidden.

**Q6.** An application-based cookie generated by the LOAD BALANCER has which name?

- A. AWSALB
- B. AWSALBAPP
- C. AWSELB
- D. AWSALBTG

**Answer: B.** The application cookie is generated by the load balancer and named AWSALBAPP.

*Why not the others:* A — the ALB duration-based cookie. C — the CLB duration-based cookie. D — reserved, not described as a stickiness cookie name.

**Q7.** Duration-based stickiness cookies are named what for ALB and CLB?

- A. ALB: AWSALB; CLB: AWSELB
- B. ALB: AWSELB; CLB: AWSALB

*Why not the others:* B — swapped. C — that's the application cookie. D — custom names are application-based.

**Q8.** An LB spans two AZs. AZ1 has 2 instances and AZ2 has 8. Each LB node gets 50% of traffic. With cross-zone load balancing ENABLED, what share does each instance get?

- A. 10% each
- B. AZ1 instances 25% each; AZ2 instances 6.25% each
- C. 50% each in AZ1
- D. 5% each

**Answer: A.** With cross-zone, each LB node distributes evenly across all registered instances in all AZs: 100% / 10 = 10%.

*Why not the others:* B — that's without cross-zone. C and D — wrong math.

**Q9.** Same setup (AZ1: 2 instances, AZ2: 8), with cross-zone DISABLED. What share does each instance in AZ1 get?

- A. 10%
- B. 25%
- C. 6.25%
- D. 50%

**Answer: B.** Without cross-zone, each node splits its 50% only among its own AZ's instances: AZ1 50/2 = 25% each; AZ2 50/8 = 6.25% each.

*Why not the others:* A — the cross-zone result. C — the AZ2 share. D — the node share, not the instance share.

**Q10.** A team using an NLB enables cross-zone load balancing. What should they expect on the bill?

- A. Nothing changes
- B. Charges for inter-AZ data
- C. A flat $50/month fee
- D. Cross-zone can't be enabled on NLB

**Answer: B.** NLB and GWLB have cross-zone disabled by default, and you pay for inter-AZ data if you enable it.

*Why not the others:* A — that's ALB/CLB. C — made up. D — it can be enabled.

**Q11.** Which statement about ALB cross-zone load balancing is correct?

- A. Disabled by default; charged when enabled
- B. Enabled by default, can be disabled at the target group level, and no charges for inter-AZ data
- C. Can never be disabled
- D. Only available in one AZ

**Answer: B.** As on the slide.

*Why not the others:* A — NLB/GWLB behavior. C — it can be disabled per target group. D — nonsensical.

**Q12.** Edge case: a CLB has cross-zone enabled. Are there inter-AZ data charges?

- A. Yes
- B. No; CLB cross-zone is disabled by default but has no charges for inter-AZ data if enabled

## Topic 27 — Route 53 Routing Policies

| --- | --- | --- | --- |

## Topic 28 — Route 53 Health Checks

Covers: the three health check types, public-only HTTP checks, global checkers and the 18% rule, passing status codes, 5120-byte text match, threshold and interval, protocols, firewall allow-listing, calculated health checks (OR/AND/NOT, 256 children), private resources via CloudWatch alarms.

**Q1.** What are the three kinds of Route 53 health checks? (Choose TWO that are on the list.)

- D. Health checks that read S3 objects
- E. Health checks that query RDS directly

**Answer: A and B.** The third type monitors an endpoint (application, server, other AWS resource).

*Why not the others:* C, D and E — not health check types.

**Q2.** An app runs on EC2 in a private subnet with no public endpoint. The team wants Route 53 DNS failover based on its health. How?

- C. Use a calculated health check alone
- D. It's impossible

**Answer: B.** Route 53 health checkers are outside the VPC and can't reach private endpoints (private VPC or on-premises). HTTP health checks are only for public resources.

*Why not the others:* A — checkers can't reach it. C — a calculated check still needs child checks that work. D — the CloudWatch approach works.

**Q3.** Which status codes make a Route 53 endpoint health check pass?

- A. Only 200
- B. 2xx and 3xx

## Topic 29 — Domain Registrar vs DNS Service, Hybrid DNS & Resolver Endpoints

Covers: registrar vs DNS service, using a third-party registrar with Route 53 (hosted zone + NS update), Route 53 Resolver defaults, hybrid DNS networks, Inbound vs Outbound Resolver Endpoints.

| Endpoint | Direction | Use |
| --- | --- | --- |
| Inbound | On-prem resolvers to Route 53 Resolver | On-prem resolves AWS names and private hosted zone records |
| Outbound | Route 53 Resolver to on-prem resolvers | VPC resources resolve on-prem names |

**Q1.** A company bought example.com from GoDaddy but wants Route 53 to manage its DNS records. What are the steps?

- A. Create a public hosted zone in Route 53, then update the NS records on the GoDaddy website to use the Route 53 name servers

- C. Create a CNAME on GoDaddy pointing to Route 53
- D. Create a private hosted zone

**Answer: A.** Domain Registrar is not the same as DNS Service; you can buy from a third party and still use Route 53 for DNS.

*Why not the others:* B — a transfer isn't required. C — delegation uses NS records, not CNAME. D — private zones don't serve the internet.

**Q2.** Which statement about registrars and DNS services is correct?

- A. They're always the same provider

- C. Route 53 can't register domains
- D. GoDaddy can't host DNS

**Answer: B.** You pay a registrar annual charges, and it usually provides DNS, but you can use another DNS service.

*Why not the others:* A — false. C — Route 53 is also a registrar. D — registrars usually provide DNS.

**Q3.** By default, which queries does the Route 53 Resolver in a VPC answer? (Choose TWO.)

- A. Records in Private Hosted Zones

- C. On-premises DNS names, automatically

**Answer: A and B.** Also records in public name servers.

**Q4.** On-premises servers (over Direct Connect) must resolve app.aws.private, a record in a Route 53 private hosted zone. What's needed?

**Q5.** EC2 instances in a VPC must resolve web.onpremise.private, hosted on the company's on-prem DNS servers over VPN. What's needed?

**Q7.** What does "Hybrid DNS" mean in the slides?
