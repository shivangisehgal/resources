# SAA-C03 Scenario Question Bank — Slides 1–117

## How to use this bank

This bank has 14 topics covering every slide from "Getting started with AWS" through "EBS vs EFS – Elastic File System" (slide 117), with 10–22 scenario questions each (209 in total). Questions mirror SAA-C03 style: single-answer and "choose TWO" items, with distractors built from the exact edge cases on the slides.

Each question is followed by the answer, why it is right, and why every other option is wrong. Cover the answer line, commit to a choice, then read the reasoning — the "why not" lines are where most exam points are won.

Where a slide fact has moved on in current AWS (for example, EC2 Instance Connect now supports more AMIs than Amazon Linux 2), the question tests the slide's version and a short note flags the difference.

## Topic 1 — AWS Global Infrastructure

Covers: Regions, Availability Zones, data centers, edge locations / Points of Presence, choosing a Region, global vs Region-scoped services.

**Q1.** A German bank must ensure customer data never leaves the EU unless it explicitly moves it. It is choosing where to deploy a new application. Which factor should drive the Region choice FIRST?

- A. The Region with the lowest price
- B. Compliance with data governance and legal requirements
- C. The Region with the most edge locations
- D. The Region with the newest services

**Answer: B.** The slide lists four Region-selection factors; compliance comes first because data never leaves a Region without your explicit permission, which is exactly the legal requirement here.

*Why not the others:* A — pricing is a valid factor but cannot override a legal mandate. C — edge locations serve CloudFront content delivery; they are not where you choose to host an application. D — service availability matters only once legal constraints are met.

**Q2.** A gaming startup's players are almost all in Australia. Latency is their top complaint. All candidate Regions are legally acceptable and offer every service they need. Which Region-selection factor applies most directly?

- A. Proximity to customers
- B. Pricing
- C. Available services
- D. Number of AZs in the Region

**Answer: A.** Proximity to customers reduces latency, so a Region such as ap-southeast-2 (Sydney) is the natural choice.

*Why not the others:* B — cost does not fix latency. C — the scenario states all Regions offer the needed services. D — AZ count affects high availability, not distance to users.

**Q3.** A team plans to use a brand-new AWS service announced last week. Their preferred Region is a smaller, recently opened one. What risk should the architect flag?

- A. New services are always launched in every Region at once
- B. New services and features aren't available in every Region
- C. New services are global and don't need a Region
- D. New services run only from edge locations

**Answer: B.** The slide explicitly warns that new services and features are not in every Region; check the Region Table before committing.

*Why not the others:* A — false; rollouts are staggered. C — most AWS services are Region-scoped; only a few (IAM, Route 53, CloudFront, WAF) are global. D — edge locations cache and deliver content; they do not host arbitrary services.

**Q4.** An architect is told a new Region has just launched. What is the MINIMUM number of Availability Zones it will have, according to the slides?

- A. 1
- B. 2
- C. 3
- D. 6

**Answer: C.** Each Region has usually 3 AZs, minimum 3, maximum 6.

*Why not the others:* A and B — below the stated minimum. D — 6 is the maximum, not the minimum.

**Q5.** Which statement BEST describes an Availability Zone?

- A. A single server rack inside a data center
- B. One or more discrete data centers with redundant power, networking and connectivity, isolated from other AZs
- C. A cluster of Regions in one geography
- D. A CloudFront caching site

**Answer: B.** That is the slide's definition: AZs are separate from each other so they are isolated from disasters, yet connected with high-bandwidth, ultra-low-latency networking.

*Why not the others:* A — an AZ is far larger than a rack. C — inverted: a Region is a cluster of data centers containing AZs. D — that is an edge location / Point of Presence.

**Q6.** A company wants a disaster in one facility (fire, flood) not to take down its whole application, while keeping very low latency between application tiers. What is the right deployment pattern?

- A. Deploy across multiple AZs in the same Region
- B. Deploy in a single AZ
- C. Deploy only at edge locations
- D. Deploy in multiple Regions with no replication

**Answer: A.** AZs are isolated from each other's disasters but linked by ultra-low-latency networking, which gives both resilience and low inter-tier latency.

*Why not the others:* B — one AZ is a single failure domain. C — edge locations don't run application tiers. D — cross-Region adds latency between tiers and, with no replication, doesn't actually protect the data.

**Q7.** A video platform wants users worldwide to download static content with lower latency without deploying servers in every country. Which part of AWS global infrastructure is designed for this?

- A. Availability Zones
- B. Regions
- C. Edge Locations / Points of Presence
- D. Placement groups

**Answer: C.** AWS has 400+ Points of Presence (400+ edge locations and 10+ regional caches) in 90+ cities across 40+ countries, delivering content to end users with lower latency (used by CloudFront).

*Why not the others:* A and B — hosting in Regions/AZs means deploying infrastructure, which the company wants to avoid; there are far fewer Regions than edge locations. D — placement groups control EC2 placement within/among AZs, not global delivery.

**Q8.** A security engineer creates an IAM user while the console is set to eu-west-3. A colleague switches the console to us-east-1. What will the colleague see?

- A. The user is missing; IAM is Region-scoped
- B. The user exists; IAM is a global service
- C. The user exists only after it is copied to us-east-1
- D. The user is visible but cannot sign in from us-east-1

**Answer: B.** IAM is listed as a Global service; users, groups, roles and policies are not tied to a Region.

*Why not the others:* A and C — treat IAM as Region-scoped, which it isn't. D — there's no Region-based sign-in restriction on IAM users.

**Q9.** Which TWO of the following services are global rather than Region-scoped? (Choose TWO.)

- A. Amazon EC2
- B. Amazon Route 53
- C. AWS Lambda
- D. AWS WAF
- E. AWS Elastic Beanstalk

**Answer: B and D.** The slide's global services are IAM, Route 53 (DNS), CloudFront (CDN) and WAF.

*Why not the others:* A (IaaS), C (FaaS) and E (PaaS) are all listed as Region-scoped. Rekognition (SaaS) is also Region-scoped.

**Q10.** A developer launched an EC2 instance in us-east-1 but can't find it in the console. The console currently shows ap-south-1. What is the most likely explanation?

- A. EC2 instances are global and should appear everywhere
- B. EC2 is Region-scoped; the console must be switched to us-east-1
- C. The instance was terminated
- D. IAM permissions differ per Region

**Answer: B.** Most AWS services, including EC2, are Region-scoped, so resources only appear in the Region they were created in.

*Why not the others:* A — EC2 is not global. C — possible but not the most likely given the Region mismatch. D — IAM is global; permissions aren't per-Region by default.

**Q11.** An architect must compare costs of running the same workload in two Regions. Which statement from the slides is correct?

- A. Pricing is identical in all Regions
- B. Pricing varies Region to Region and is transparent on each service's pricing page
- C. Pricing is only known after the first bill
- D. Pricing depends only on the number of AZs

**Answer: B.** Pricing is a Region-selection factor precisely because it varies by Region, and it is published openly.

*Why not the others:* A — false. C — prices are published in advance. D — AZ count is not a pricing driver.

**Q12.** Which naming pattern correctly identifies a Region and one of its Availability Zones?

- A. Region: ap-southeast-2a, AZ: ap-southeast-2
- B. Region: ap-southeast-2, AZ: ap-southeast-2a
- C. Region: sydney-1, AZ: sydney-1-zoneA
- D. Region and AZ share the same name

**Answer: B.** Regions look like us-east-1 or ap-southeast-2; AZs add a letter suffix (ap-southeast-2a, 2b, 2c).

*Why not the others:* A — reversed. C — not AWS naming. D — AZs always add a suffix.

## Topic 2 — IAM (Identity & Access Management)

Covers: root account, users and groups, policies and inheritance, policy structure, password policy, MFA and device types, Console / CLI / SDK access, access keys, IAM roles for services, Credentials Report, Access Advisor, best practices.

**Q1.** A startup's founder has been using the root account daily to launch EC2 instances. What should the architect recommend?

- A. Keep using root but enable MFA
- B. Use the root account only for account setup; create IAM users for daily work
- C. Share root credentials with the ops team so they can help
- D. Delete the root account

**Answer: B.** The root account is created by default and shouldn't be used or shared, except for account setup.

*Why not the others:* A — MFA on root is good, but daily root use still violates best practice. C — never share root or IAM credentials. D — the root account can't simply be removed and is still needed for setup tasks.

**Q2.** An admin wants to create a group "Engineering" that contains the existing groups "Developers" and "Operations" so permissions flow down. What happens?

- A. It works; groups can be nested
- B. It fails; groups only contain users, not other groups
- C. It works only if both groups have no inline policies
- D. It works only with AWS Organizations

**Answer: B.** Groups contain users only; nesting groups is not possible.

*Why not the others:* A — nesting isn't supported. C — inline policies are irrelevant to nesting. D — Organizations doesn't enable IAM group nesting.

**Q3.** Charles is a member of both the "Developers" and "Audit Team" groups. Fred belongs to no group. Which statement is correct?

- A. Charles must leave one group; users can belong to only one group
- B. Fred's account is invalid until he joins a group
- C. Both are valid: users can belong to multiple groups or to none
- D. Fred inherits permissions from all groups by default

**Answer: C.** Users don't have to belong to a group, and a user can belong to multiple groups.

*Why not the others:* A — multiple membership is allowed. B — group membership is optional. D — a user gets permissions only from groups he is in, plus policies attached directly to him.

**Q4.** Fred is not in any group but needs read access to one S3 bucket. What is the best way to grant it, based on the slides?

- A. Attach a policy (e.g., an inline policy) directly to the user Fred
- B. Create a group for Fred and nest it under Developers
- C. Give Fred the root credentials
- D. Give Fred the Developers group's access keys

**Answer: A.** Policies can be assigned to users or groups; the inheritance slide shows an inline policy attached directly to a user who is not in a group.

*Why not the others:* B — nesting isn't allowed. C — never share root. D — groups don't have access keys; keys belong to individual users and must never be shared.

**Q5.** An auditor finds a policy granting `"Action": "*"` on `"Resource": "*"` to every developer, although they only need to describe EC2 instances. Which principle is violated?

- A. Shared responsibility
- B. Least privilege
- C. Defense in depth
- D. Elasticity

**Answer: B.** AWS applies the least privilege principle: don't give more permissions than a user needs.

*Why not the others:* A — shared responsibility splits duties between AWS and customer. C — related but not the specific principle named for over-broad permissions. D — a scaling concept.

**Q6.** Which elements of an IAM policy are OPTIONAL? (Choose TWO.)

- A. Version
- B. Statement
- C. Id
- D. Sid
- E. Effect

**Answer: C and D.** Id (policy identifier) and Sid (statement identifier) are optional; Condition is also optional.

*Why not the others:* A — the slide says always include Version "2012-10-17". B — Statement is required (one or more). E — every statement needs Effect (Allow or Deny).

**Q7.** A policy must allow access only when a request comes from the corporate IP range. Which policy element expresses this?

- A. Principal
- B. Resource
- C. Condition
- D. Sid

**Answer: C.** Condition defines when the policy is in effect.

*Why not the others:* A — Principal is who the policy applies to (account/user/role). B — Resource is what the actions apply to. D — Sid is just a label.

**Q8.** A policy document uses "Version": "2024-01-01". What does the architect correct it to?

- A. Today's date
- B. "2012-10-17"
- C. Remove Version entirely; it's optional
- D. The account creation date

**Answer: B.** Version is the policy language version and should always be "2012-10-17".

*Why not the others:* A and D — Version is not a timestamp you choose. C — the slide says always include it.

**Q9.** Security wants IAM users to rotate passwords every 90 days, include at least one symbol, and not reuse old passwords. Which TWO password-policy settings help? (Choose TWO.)

- A. Require non-alphanumeric characters
- B. Require users to change their password after some time (password expiration)
- C. Require MFA for password changes
- D. Lock users out of changing their own passwords
- E. Require access keys for console login

**Answer: A and B.** Both are listed password-policy options. Preventing password re-use (also on the slide) covers the third requirement.

*Why not the others:* C — MFA is separate from the password policy. D — the policy option is the opposite: allow users to change their own passwords. E — access keys are for CLI/SDK, not console.

**Q10.** An attacker phished an IAM user's console password. The user had MFA enabled. What is the outcome?

- A. The account is compromised; MFA only protects root
- B. The account is not compromised because the attacker lacks the security device
- C. The account is compromised unless a password policy exists
- D. MFA only applies to the CLI

**Answer: B.** MFA = password you know + security device you own. Main benefit: if a password is stolen or hacked, the account is not compromised.

*Why not the others:* A — MFA can protect both root and IAM users. C — a password policy doesn't stop use of a stolen password. D — MFA protects console logins on the slide.

**Q11.** A security team wants ONE physical device that can serve as MFA for the root user and several IAM users. Which option fits best?

- A. Virtual MFA app on a phone (Google Authenticator / Authy)
- B. Universal 2nd Factor (U2F) security key such as YubiKey
- C. Hardware key fob for AWS GovCloud (SurePassID)
- D. SMS text codes

**Answer: B.** The slide notes U2F keys (YubiKey, third-party) support multiple root and IAM users using a single security key.

*Why not the others:* A — virtual MFA supports multiple tokens on a single phone, but it's an app, not a dedicated physical security key. C — specifically for GovCloud (US). D — not listed as an AWS MFA option.

**Q12.** A US government agency works in AWS GovCloud (US) and needs a hardware MFA device. Which option is listed for this?

- A. YubiKey U2F
- B. Hardware key fob by Gemalto
- C. Hardware key fob by SurePassID
- D. Authy

**Answer: C.** The GovCloud hardware key fob is provided by SurePassID.

*Why not the others:* A — general U2F key. B — Gemalto provides the standard (non-GovCloud) hardware fob. D — virtual phone app.

**Q13.** A developer needs to automate S3 uploads from a shell script on her laptop. What should she use to authenticate?

- A. Console username and password
- B. Access keys (Access Key ID + Secret Access Key) with the AWS CLI
- C. The root user's MFA device
- D. An IAM group's credentials

**Answer: B.** The CLI and SDK are protected by access keys; Access Key ID \~= username, Secret Access Key \~= password.

*Why not the others:* A — password + MFA protects the Management Console, not CLI scripts. C — never use root for this. D — groups have no credentials.

**Q14.** A junior engineer asks the admin to generate and email him access keys. What does best practice say?

- A. Admins generate keys and share them by email
- B. Users generate and manage their own access keys through the AWS Console, and keep them secret
- C. Keys are generated by AWS Support
- D. One set of keys should be shared by the whole team

**Answer: B.** Access keys are generated through the Console, users manage their own, and keys are secret like a password.

*Why not the others:* A — emailing keys exposes them. C — not how keys are created. D — never share IAM users or keys (one physical user = one AWS user).

**Q15.** Which statement about the AWS CLI and AWS SDK is correct?

- A. The CLI is closed-source and unrelated to the SDK
- B. The CLI is open-source and built on the AWS SDK for Python
- C. The SDK only supports Java
- D. The SDK cannot be used on mobile or IoT devices

**Answer: B.** The CLI is open-source (github.com/aws/aws-cli) and built on the SDK for Python (boto).

*Why not the others:* A — false on both counts. C — SDKs exist for JavaScript, Python, PHP, .NET, Ruby, Java, Go, Node.js, C++. D — there are Mobile SDKs (Android, iOS) and IoT Device SDKs (Embedded C, Arduino).

**Q16.** An application running on EC2 must read from DynamoDB. A developer plans to store access keys in a config file on the instance. What is the better approach?

- A. Store access keys in EC2 User Data
- B. Attach an IAM Role (EC2 Instance Role) to the instance
- C. Use the root account's access keys
- D. Create an IAM group for the instance

**Answer: B.** AWS services that act on your behalf get permissions through IAM Roles; EC2 Instance Roles are the common example.

*Why not the others:* A — still hard-coded credentials, and User Data is readable. C — never use root keys. D — groups contain users, not EC2 instances.

**Q17.** A compliance officer needs one report listing ALL IAM users in the account and the status of their passwords, access keys and MFA. Which tool fits?

- A. IAM Access Advisor
- B. IAM Credentials Report
- C. AWS CloudTrail
- D. Password policy

**Answer: B.** The Credentials Report is account-level and lists all users and the status of their credentials.

*Why not the others:* A — Access Advisor is user-level and shows services and last access. C — not part of the IAM security tools on these slides. D — sets rules, doesn't report.

**Q18.** An admin suspects the user "Bob" has permissions to many services he never uses and wants to tighten Bob's policies. Which tool helps most?

- A. IAM Credentials Report
- B. IAM Access Advisor
- C. MFA
- D. EC2 Instance Roles

**Answer: B.** Access Advisor shows service permissions granted to a user and when they were last accessed, so you can revise policies (least privilege).

*Why not the others:* A — shows credential status, not service usage. C and D — unrelated to permission auditing.

## Topic 3 — EC2 Basics: Configuration, User Data, Instance Types

Covers: what EC2 is (IaaS), sizing and configuration options, EC2 User Data, instance naming, and the four instance families with their use cases.

**Q1.** A manager asks which service model EC2 represents and what capabilities come with it. Which answer is accurate?

- A. PaaS; it includes managed databases
- B. IaaS; renting VMs (EC2), storing data on virtual drives (EBS), distributing load (ELB), scaling with ASG
- C. SaaS; it includes image recognition
- D. FaaS; it runs code without servers

**Answer: B.** EC2 = Elastic Compute Cloud = Infrastructure as a Service, and the slide lists EC2, EBS, ELB and ASG as its core capabilities.

*Why not the others:* A — Elastic Beanstalk is the PaaS example. C — Rekognition is the SaaS example. D — Lambda is the FaaS example.

**Q2.** Which TWO storage options are network-attached to an EC2 instance? (Choose TWO.)

- A. Amazon EBS
- B. EC2 Instance Store
- C. Amazon EFS
- D. Instance RAM
- E. EC2 User Data

**Answer: A and C.** The sizing slide lists network-attached storage as EBS & EFS.

*Why not the others:* B — instance store is hardware storage physically attached to the host. D — RAM is memory, not storage. E — User Data is a bootstrap script.

**Q3.** Every new web server must install security updates, install Apache and download a config file when it first launches — with no manual login. What should be used?

- A. EC2 User Data script
- B. A security group rule
- C. An Elastic IP
- D. EC2 Instance Connect

**Answer: A.** User Data bootstraps instances: installing updates and software, downloading files from the internet, anything at first launch.

*Why not the others:* B — SGs are firewalls. C — an EIP is a fixed public IP. D — Instance Connect is for manual browser-based SSH, the opposite of automation.

**Q4.** An engineer edits a User Data script and reboots an existing instance, expecting the script to re-run. It doesn't. Why?

- A. User Data runs only once, at the instance's first start
- B. User Data runs only on Windows
- C. The script lacks root permission
- D. User Data runs only when the instance is terminated

**Answer: A.** The slide states the script is only run once at the instance first start. (The Hibernate slide repeats this: first start = OS boots and User Data runs; following starts = only the OS boots.)

*Why not the others:* B — it works on Linux too. C — User Data runs as the root user. D — nonsensical; termination ends the instance.

**Q5.** A User Data script runs `yum install -y httpd` without `sudo`. Will it succeed?

- A. No; User Data runs as ec2-user
- B. Yes; the EC2 User Data script runs with the root user
- C. No; User Data cannot install packages
- D. Only if the instance has an IAM role

**Answer: B.** User Data runs as root, so sudo isn't needed.

*Why not the others:* A — incorrect user. C — installing software is a listed use case. D — package installs from repos don't depend on an IAM role.

**Q6.** In the instance type `m5.2xlarge`, what does the "5" represent?

- A. The instance class
- B. The generation
- C. The size within the class
- D. The number of vCPUs

**Answer: B.** m = instance class, 5 = generation (AWS improves them over time), 2xlarge = size within the class.

*Why not the others:* A — that's "m". C — that's "2xlarge". D — vCPU count isn't encoded as that digit.

**Q7.** A company runs a mix of web servers and code repositories with a balanced need for compute, memory and networking. Which family is the best default?

- A. General Purpose
- B. Compute Optimized
- C. Memory Optimized
- D. Storage Optimized

**Answer: A.** General Purpose balances compute, memory and networking; web servers and code repositories are its listed workloads (t2.micro is general purpose).

*Why not the others:* B, C and D each optimize one dimension and cost more for an unbalanced profile.

**Q8.** A media company runs large batch video transcoding and scientific modeling jobs. Which family fits?

- A. Memory Optimized
- B. Compute Optimized
- C. Storage Optimized
- D. General Purpose

**Answer: B.** Compute Optimized is for compute-intensive tasks: batch processing, media transcoding, high-performance web servers, HPC, scientific modeling & ML, dedicated gaming servers.

*Why not the others:* A — for large in-memory data sets. C — for high sequential I/O on local storage. D — balanced, not top CPU performance.

**Q9.** A BI team needs an in-memory database and real-time processing of big unstructured data. Which family fits?

- A. Memory Optimized
- B. Compute Optimized
- C. Storage Optimized
- D. General Purpose

**Answer: A.** Memory Optimized gives fast performance for workloads that process large data sets in memory: high-performance relational/non-relational DBs, distributed web-scale cache stores, in-memory DBs optimized for BI, real-time processing of big unstructured data.

*Why not the others:* B — CPU-focused. C — local disk I/O focused. D — not enough memory for this profile.

**Q10.** A high-frequency OLTP system needs very high sequential read/write access to large data sets on local storage. Which family fits?

- A. Storage Optimized
- B. Memory Optimized
- C. Compute Optimized
- D. General Purpose

**Answer: A.** Storage Optimized use cases: high-frequency OLTP, relational & NoSQL DBs, cache for in-memory DBs (e.g., Redis), data warehousing, distributed file systems.

*Why not the others:* B — tempting for databases, but the key phrase is "high sequential read/write on local storage". C and D — not optimized for local disk throughput.

**Q11.** Edge case: "Relational & NoSQL databases" appears in which TWO families' use-case lists? (Choose TWO.)

- A. Memory Optimized (high performance relational/non-relational databases)
- B. Storage Optimized (relational & NoSQL databases)
- C. Compute Optimized
- D. General Purpose
- E. None; databases must use RDS

**Answer: A and B.** Databases appear in both. On the exam, decide by the clue: "large data sets in memory" points to Memory Optimized; "high sequential I/O to local storage" or OLTP points to Storage Optimized.

*Why not the others:* C and D — databases aren't listed there. E — you can run databases on EC2.

**Q12.** From the example table, which instance has local NVMe SSD instance storage instead of being EBS-only?

- A. t2.micro
- B. r5.16xlarge
- C. c5d.4xlarge
- D. m5.8xlarge

**Answer: C.** c5d.4xlarge has 1 x 400 NVMe SSD; the "d" suffix indicates local disk. The others are EBS-only.

*Why not the others:* A, B and D — listed as EBS-only.

**Q13.** Which of these is configured when you size an EC2 instance, according to the slides? (Choose TWO.)

- A. Firewall rules via a security group
- B. The Region's number of AZs
- C. A bootstrap script via EC2 User Data
- D. The IAM password policy
- E. Route 53 hosted zone

**Answer: A and C.** EC2 configuration options include OS, CPU, RAM, storage, network card / public IP, firewall rules (security group) and bootstrap script (User Data).

*Why not the others:* B — fixed by AWS. D — account-level IAM setting. E — DNS, not EC2 config.

**Q14.** Which operating systems can EC2 instances run, per the slides?

- A. Linux only
- B. Linux and Windows only
- C. Linux, Windows or Mac OS
- D. Any OS, including mainframe z/OS

**Answer: C.** The configuration slide lists Linux, Windows or Mac OS.

*Why not the others:* A and B — incomplete. D — not listed.

## Topic 4 — Security Groups, Classic Ports, SSH & EC2 Instance Connect

Covers: what SGs regulate, default inbound/outbound behavior, scope (Region/VPC), attaching to multiple instances, referencing other SGs, timeout vs connection refused, classic ports, SSH methods, EC2 Instance Connect.

**Q1.** A newly launched EC2 web server has a security group with no inbound rules. Users get a timeout on port 80. Why?

- A. All inbound traffic is blocked by default
- B. All outbound traffic is blocked by default
- C. The application crashed
- D. Port 80 requires an Elastic IP

**Answer: A.** By default, all inbound traffic is blocked and all outbound traffic is authorised. You must add an inbound rule for port 80.

*Why not the others:* B — outbound is allowed by default. C — a crashed app gives "connection refused", not a timeout. D — an EIP isn't needed for HTTP.

**Q2.** A user connecting to an EC2 app on port 8080 receives "connection refused". The security group allows 8080 from 0.0.0.0/0. What is the most likely cause?

- A. A security group misconfiguration
- B. An application error, or the application is not launched
- C. The NACL is blocking inbound
- D. The instance is in the wrong Region

**Answer: B.** Timeout = security group issue; "connection refused" = application error or not launched. Traffic reached the instance, so the SG let it through.

*Why not the others:* A — an SG block causes a timeout, not a refusal. C — NACLs aren't in this section, and a block would also time out. D — a wrong Region would mean no reachable endpoint at all.

**Q3.** An app server must accept port 123 traffic only from instances that have "SG-Web" attached, regardless of their changing IP addresses. What is the cleanest rule?

- A. Allow port 123 from each instance's current private IP
- B. Allow port 123 with SG-Web as the source (reference the security group)
- C. Allow port 123 from 0.0.0.0/0
- D. Attach SG-Web to the app server

**Answer: B.** Security group rules can reference by IP or by security group. Instances with SG-Web attached are authorised whatever their IPs; instances with a different SG (e.g., SG3) are not.

*Why not the others:* A — breaks when IPs change and doesn't scale. C — opens to the world. D — attaching SG-Web to the server governs the server's own traffic; it doesn't define who may reach it.

**Q4.** An admin wants to reuse the same security group across 20 EC2 instances in the same VPC. Is that allowed?

- A. No, one SG per instance
- B. Yes, a security group can be attached to multiple instances
- C. Only if they are in the same AZ
- D. Only with a Dedicated Host

**Answer: B.** SGs can be attached to multiple instances (and an instance can have multiple SGs).

*Why not the others:* A — false. C — the scope is Region/VPC, not AZ. D — unrelated.

**Q5.** A team creates a security group in us-east-1 and tries to attach it to an instance in eu-west-1. What happens?

- A. It works; SGs are global
- B. It fails; SGs are locked down to a Region / VPC combination
- C. It works if both VPCs share a CIDR
- D. It works after copying the SG automatically

**Answer: B.** Security groups are locked to a Region/VPC combination; create a new one in the other Region/VPC.

*Why not the others:* A — SGs aren't global. C — CIDR overlap is irrelevant. D — there's no automatic copy.

## Topic 7 — Placement Groups (Cluster, Spread, Partition)

Covers: the three strategies, their pros/cons, limits (7 per AZ for spread, 7 partitions per AZ), multi-AZ capability, partition metadata, and use cases.

**Q1.** A big-data job must finish as fast as possible, with extremely low latency and high throughput between nodes. Losing the job if an AZ fails is acceptable. Which strategy?

- A. Cluster
- B. Spread
- C. Partition
- D. No placement group, spread across Regions

**Answer: A.** Cluster groups instances in a single AZ for low latency and up to 10 Gbps between instances with Enhanced Networking. Use cases: big data jobs that must complete fast, apps needing extremely low latency and high network throughput.

*Why not the others:* B — maximizes isolation, not network speed. C — for large distributed systems with rack isolation. D — cross-Region adds latency.

**Q2.** What is the main DRAWBACK of a cluster placement group?

- A. Limited to 7 instances
- B. If the AZ fails, all instances fail at the same time
- C. No Enhanced Networking support
- D. Instances can't communicate

**Answer: B.** All instances are in the same AZ, so an AZ failure takes them all out.

*Why not the others:* A — that's the spread limit. C — Enhanced Networking is recommended for cluster. D — the opposite: they get the best network.

**Q3.** A critical app runs on 6 instances, and each must be isolated from the others' hardware failure. Which strategy maximizes high availability?

- A. Cluster
- B. Spread
- C. Partition
- D. Dedicated Instances

**Answer: B.** Spread places each instance on different physical hardware and can span AZs, reducing the risk of simultaneous failure — for critical apps where each instance must be isolated.

*Why not the others:* A — shares one AZ and failure domain. C — isolates groups (partitions), not each instance. D — a tenancy option, not a placement strategy.

**Q4.** A team wants 15 instances in a single spread placement group, all in us-east-1a. What happens?

- A. It works
- B. It fails: spread allows a maximum of 7 instances per AZ per group
- C. It works only with Dedicated Hosts
- D. It works if half are Spot

**Answer: B.** The spread limit is 7 instances per AZ per placement group.

*Why not the others:* A — exceeds the limit. C and D — neither changes the limit.

**Q5.** Edge case: a spread placement group spans 3 AZs in a Region. What is the maximum number of instances it can hold?

- A. 7
- B. 14
- C. 21
- D. Hundreds

**Answer: C.** 7 instances per AZ x 3 AZs = 21.

*Why not the others:* A — that's per AZ. B — would be 2 AZs. D — partition groups scale to hundreds, spread doesn't.

**Q6.** A Cassandra cluster of 300 nodes needs rack-level fault isolation, so a rack failure affects only part of the cluster. Which strategy?

- A. Cluster
- B. Spread
- C. Partition
- D. None

**Answer: C.** Partition spreads instances across partitions on different sets of racks, scales to 100s of instances, and suits HDFS, HBase, Cassandra and Kafka.

*Why not the others:* A — one failure domain. B — limited to 7 per AZ, far below 300. D — no isolation guarantees.

**Q7.** What is the maximum number of partitions per AZ in a partition placement group?

- A. 3
- B. 7
- C. 16
- D. 100

**Answer: B.** Up to 7 partitions per AZ (each partition can hold many instances).

*Why not the others:* A — too low. C — that's the EBS Multi-Attach instance limit. D — "100s" refers to instances, not partitions.

**Q8.** A Kafka application must know which partition each broker is in, to place replicas correctly. How does it get this?

- A. EC2 instances get access to the partition information as metadata
- B. Via an IAM Credentials Report
- C. Via the Elastic IP
- D. It isn't possible

**Answer: A.** In a partition placement group, instances get partition information as metadata, so partition-aware apps can place replicas.

*Why not the others:* B — IAM reporting is unrelated. C — unrelated. D — it is possible.

**Q9.** Which placement strategies can span multiple AZs in the same Region? (Choose TWO.)

- A. Cluster
- B. Spread
- C. Partition
- D. None of them
- E. All three

**Answer: B and C.** Spread can span AZs, and partition can span multiple AZs in the same Region.

*Why not the others:* A — cluster is a single AZ. D and E — contradicted by the above.

**Q10.** In a partition placement group, partition 2's rack loses power. What is the impact?

- B. Many instances in partition 2 may fail, but other partitions are not affected
- C. Only one instance fails

**Q1.** A company must encrypt an existing unencrypted EBS data volume attached to a running app server. What's the correct sequence?

**Answer: B.** That's the slide's four-step process; the new volume is encrypted because it comes from an encrypted snapshot.

*Why not the others:* A — you can't flip encryption on an existing volume in place. C — no such operation. D — encryption isn't an instance setting.

**Q2.** Which step in the process actually introduces encryption?

- A. Creating the first snapshot

*Why not the others:* A — a snapshot of an unencrypted volume is unencrypted. C — attaching doesn't change encryption. D — not part of encryption.

**Q3.** When you create an encrypted EBS volume, which are encrypted? (Choose TWO.)

## Topic 14 — Amazon EFS & EBS vs EFS vs Instance Store

Covers: EFS basics (managed NFS, multi-AZ, NFSv4.1, SG access, Linux/POSIX only, KMS at rest, pay-per-use), scale, performance modes, throughput modes, storage tiers and lifecycle, Standard vs One Zone, mount targets, and the EBS vs EFS vs instance store decision.

|  | EBS | EFS | Instance Store |
| --- | --- | --- | --- |
| Attach | One instance (except io1/io2 Multi-Attach, same AZ, up to 16) | 100s of instances across AZs | Only its host instance |
| Scope | Locked to one AZ (move via snapshot) | Multi-AZ (Standard) or One Zone | Host hardware |
| Persistence | Survives stop; root deleted on terminate by default | Independent of instances | Lost on stop / hardware failure |
| Capacity & billing | Provisioned GB + IOPS, billed for all provisioned | Scales automatically, pay per use (about 3x gp2 price) | Included with instance |
| OS | Any | Linux only (POSIX, NFSv4.1) | Any |

**Q1.** A WordPress site runs on EC2 instances across 3 AZs, and all instances must share the same uploaded media files. Which storage?

- A. Amazon EFS
- B. EBS gp3
- C. EBS io2 Multi-Attach
- D. Instance store

**Answer: A.** EFS is managed NFS mountable on many EC2 instances across multiple AZs; WordPress, content management, web serving and data sharing are listed use cases.

*Why not the others:* B — one instance and one AZ. C — Multi-Attach is same-AZ only and needs a cluster-aware file system. D — ephemeral and not shareable.

**Q2.** A team wants to mount shared EFS storage on Windows Server EC2 instances. What's the issue?
